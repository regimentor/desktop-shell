# Сервер уведомлений внутри процесса оболочки

Сервер уведомлений работает внутри постоянно живущего процесса оболочки,
вместе с панелью и лаунчером, как выбрал пользователь; закрытие окна не останавливает приём. Используем
собственный небольшой Qt D-Bus endpoint в локальном QML-модуле вместо
Quickshell.Services.Notifications: изолированный тест установленного Quickshell
0.3.1 подтвердил, что replacement сохраняет старые подписи действий, а API
не сообщает повторный Notify с идентичными свойствами. Нативный адаптер даёт
один сигнал на каждый Notify и корректный жизненный цикл действий; цена решения —
собственная поддержка протокола и сборка модуля, поэтому протокольные проверки
входят в обязательный набор тестов.

Тот же модуль сохраняет изображения и наблюдает чужую блокировку через
hyprland-lock-notify-v1. Архив содержит снимки, отделённые от живых D-Bus ID;
перезапуск процесса не восстанавливает старые действия. Ограниченная история
не рекламируется как protocol persistence. Рабочее включение явно задаётся
`DAEVOX_NOTIFICATIONS=1`, чтобы установка до миграции не перехватила имя у mako.

При объединении модулей сервер перенесён под единственный корневой `shell.qml`.
Перезапуск панели теперь перезапускает всю оболочку, прерывает приём уведомлений
и инвалидирует старые действия. Скрытие лаунчера не влияет на сервер. Модули
разделяют ответственность, но не изолируют падения; экономия памяти без измерений
не предполагается.
