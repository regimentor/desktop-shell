# Центр уведомлений и замена mako

Status: approved

Итог планирования подтверждён пользователем: «подтверждаю». Продуктовые правила ниже
согласованы в билетах [02](issues/02-history-and-behavior.md),
[03](issues/03-layout-and-interaction.md) и
[04](issues/04-migration-and-acceptance.md).
Технические детали и критерии приёмки собраны здесь как предложение реализации.
Реализация и рабочее переключение выполнены; результаты и оставшаяся приёмка
описаны в [отчёте](implementation.md).

## Область работы

Третий режим лаунчера «Уведомления» рядом с Apps и Volume, открываемый через
Alt+3; история, действия приложений, всплывающие карточки и «Не беспокоить».
Итог перехода — полный отказ от mako, включая прямой автозапуск, D-Bus
активацию и удаление пакета после успешной приёмки.

Сервер работает в существующем процессе лаунчера. Отдельного сервиса
уведомлений нет. Закрытие окна не прерывает приём. Перезапуск процесса
восстанавливает сохранённую историю и DND, но не прежние действия приложений.

## История и действия

- Хранение на диске до 7 дней, максимум 500 записей. Transient не сохраняются.
- Прочтение наступает при ручном закрытии уведомления или истечении таймера
  показанной карточки. Просмотр центра и подавление показа не означают прочтение.
- Закрытие всплывающей карточки сохраняет прочитанную запись истории.
- Удаление записи убирает её историю, изображение, черновик, popup и место
  в очереди; завершает живое уведомление и доступность действий.
  Очистка приложения и всей истории применяет то же правило ко всем записям.
- Клик по отдельной карточке вызывает доступное основное действие; если его
  нет, раскрывает полный текст. Кнопки вызывают свои действия. Поддерживаются
  изображения и быстрый ответ, если приложение и установленный API их предоставляют.
- После закрытия или перезапуска остаётся архив без неработающих кнопок.
  Resident учитывается при вызове действия согласно проверенному API.
- Обновление существующего живого уведомления заменяет запись без дублей;
  таймер показанной карточки начинается заново. Обновление скрытого через DND
  сообщения не вызывает повторного показа после выключения DND.
- Черновики ответа хранятся только в памяти: сохраняются при Esc и закрытии
  лаунчера, удаляются с уведомлением или при перезапуске процесса.

### Уточнение пользователя: изображения в метаданных

Картинка из метаданных уведомления трактуется как его аватар (например, канал
или отправитель Telegram), а не как вложение сообщения. Показывать её компактно
в заголовке карточки и на обложке стопки; при отсутствии — иконку приложения.
Правило действует на popup и историю, включая ранее сохранённые записи.
Только изображение непосредственно в теле сообщения может считаться контентом.
Поддержка body-images/markup этим изменением не добавляется.

## Центр уведомлений и клавиатура

Основа — подтверждённый вариант A из `launcher/notification-prototype.html`.
HTML — временный образец, не готовая реализация Quickshell. Его демонстрационные
переключатели и сценарии не входят в интерфейс продукта; при расхождениях
клавиатуры с HTML действуют правила этой спецификации.

- Группировка по приложениям в раскрывающиеся стопки. Стопки изначально
  свёрнуты: последнее сообщение сверху, края карточек позади, количество
  сообщений и непрочитанных. Одиночное сообщение — обычная карточка.
- Стопки отсортированы по свежести последнего сообщения; внутри новые выше.
- Нажатие на стопку раскрывает её без вызова действия приложения.
  Есть управление сворачиванием и очисткой приложения.
- Поиск по приложению, заголовку и тексту; фильтр «Непрочитанные».
  Поиск раскрывает совпадения с сохранением группировки.
- Табы режимов — только иконки, без названий и подписей хоткеев. DND, фильтр
  сообщений и очистка всей истории — также иконки с подсказками и доступными
  именами. Удаление карточки — корзина справа сверху; закрытие popup — крестик
  на том же месте с сохранением истории.
- ↑/↓ выбирают видимые стопки и карточки. Enter раскрывает стопку; на карточке
  вызывает основное действие или раскрывает текст. Tab обходит контролы.
- Esc закрывает ввод ответа, затем очищает поиск, затем скрывает лаунчер.
- Backspace вне поля ввода удаляет выбранную карточку или всю выбранную стопку.
  В поле ввода он редактирует текст. Delete не является назначенной командой.

## Всплывающие уведомления

- Справа сверху под панелью, на мониторе с активным окном. Одновременно до трёх
  карточек; остальные ожидают очереди. Предложенная трактовка лимита — три
  на весь рабочий стол, включая карточки на разных мониторах.
- Таймер начинается при появлении карточки, а не при поступлении в очередь.
  Обычный срок — 5 секунд, если приложение не запросило иной.
- Критические сообщения и сообщения с нулевым таймаутом не исчезают по таймеру.
  Наведение и ввод ответа приостанавливают таймер.
- Появление сообщения не забирает клавиатурный фокус. Поле быстрого ответа
  получает фокус после нажатия «Ответить».
- Уже показанные карточки не перемещаются вслед за активным окном; новые
  показываются на текущем активном мониторе. При отключении монитора оставшиеся
  карточки переносятся на доступный, без повторного приёма сообщения.
- Звукового сопровождения нет.

## Подавление показа

- DND скрывает все сообщения, включая критические, сохраняет историю с
  исключением transient. Состояние DND хранится после перезапуска до ручного
  выключения.
- Включение DND немедленно скрывает карточки и отменяет очередь, не помечая
  записи прочитанными. Выключение не воспроизводит накопившееся.
- Блокировка экрана действует так же на показ и очередь. При разблокировке
  показываются только новые сообщения. Центр не должен становиться доступным
  поверх экрана блокировки.
- При неизвестном состоянии блокировки показ подавлен до подтверждённой
  разблокировки; накопившиеся сообщения потом не всплывают.
- Скрытие не закрывает сохраняемые живые уведомления: их действия доступны
  в центре после разблокировки до отзыва приложением, ручного удаления или
  удаления по лимиту истории. Само снятие подавления не запускает их таймеры.

## Предложенная внутренняя архитектура

Постоянный контроллер создаётся рядом с Launcher в корне `launcher/shell.qml`.
По результатам проверки установленного API используется собственный D-Bus endpoint
в нативном модуле процесса: [ADR](../../docs/adr/0001-notifications-in-process.md).
Контроллер владеет живыми связями, архивом и политикой показа.
UI центра и popup используют один источник состояния; видимость окна не
управляет временем жизни сервера. Интерфейс не хранит самостоятельных копий
статуса прочтения, удаления или DND.

Разделить внутри контроллера:

1. Адаптер установленного API: приём, replacement, закрытие, actions, reply.
2. Архив: обычные данные с собственным стабильным ключом; живой D-Bus ID не
   используется как постоянный идентификатор между запусками.
3. Планировщик popup: очередь, монитор назначения, оставшееся время,
   паузы и подавление. Отсутствие popup не означает закрытый живой объект.
4. Хранилище истории/настроек/изображений и наблюдатель блокировки.

Технические предложения, требующие проверки в реализации:

- Ключ группировки: desktop-entry, затем имя приложения; при отсутствии обоих
  отдельная группа неизвестных приложений. Не разделять приложение по заголовку
  уведомления и не объединять его только по совпадению иконки.
- Сохранять снимок текста, приложения, времени, прочтения и ссылки на собственную
  копию изображения; не сериализовать живые QML-объекты, callback и черновики.
- Хранить данные в XDG state directory приложения, заменять файл атомарно.
  Проверять формат при загрузке; повреждённый файл не должен мешать приёму.
- Сохранять уменьшенные изображения в принадлежащем архиву каталоге; внутренний
  URL Quickshell сам по себе не является долговечным изображением.
  Ошибка копирования оставляет текст. Очищать ненужные файлы вместе с записями.
- Обрезать архив при загрузке, поступлении и периодически по времени.
  Удаление по сроку/лимиту завершает связанные живые уведомления, как согласовано.
  Для обновлений предлагается считать свежесть от последнего обновления.
- Ограничить декодируемый размер изображений, общий объём файлов и память очереди;
  конкретные технические пороги подобрать и проверить нагрузочным сценарием.
  Переполнение очереди не должно молча помечать невиденные записи прочитанными.
- Transient, подавленные без сохранения, освобождать без создания архивной записи.
- Поддержку markup и иных capabilities не объявлять без реализации и проверки;
  текст приложения не интерпретировать как произвольный HTML.

## Обязательные технические проверки

Основание: [исследование API и mako](research/platform-and-mako.md),
[проверка блокировки](issues/04-migration-and-acceptance.md).
Ниже перечислены ещё не выполненные проверки, а не подтверждённые возможности.

- В отдельной D-Bus сессии проверить Notify, replacement, CloseNotification,
  причины закрытия, actions, resident, transient и inline reply.
- Проверить таймауты -1/0/1000 на установленном пакете: исследование выявило
  расхождение единиц между документацией и исходником. Проверить обновление
  подписей действий и изображений при replacement, отслеживание изменений
  существующего объекта без нового сигнала приёма.
- Проверить копирование image-data из внутреннего image provider, закрытие
  исходного объекта и чтение сохранённой картинки после перезапуска.
- Найти проверяемый источник lock/unlock с начальным состоянием и reconnect.
  Кандидат — адаптер `hyprland-lock-notify-v1`; наличие заголовка не доказывает
  доступность и гарантии протокола в текущей сессии. `WlSessionLock` не использовать
  как наблюдатель чужой блокировки. Непроверенный LockedHint не считать истиной.
- Проверить Wayland-фокус ответа, закрытие поля, два монитора и hotplug.
- Проверить QML reload отдельно от рестарта процесса; не дублировать callbacks,
  запись истории и popup. Reload не должен восстанавливать уже подавленную очередь.

## Порядок реализации и перехода

1. Выполнить изолированные проверки API и источник блокировки. Не запускать
   пробный NotificationServer на рабочей D-Bus: он может захватить имя позже.
2. Реализовать контроллер, архив и политику показа с проверками жизненного цикла.
3. Собрать центр со стопками и всплывающие карточки, проверить клавиатуру и фокус.
4. Подготовить миграцию с резервной копией изменяемой конфигурации, фиксацией
   прежнего состояния автозапуска и готовой инструкцией отката.
5. При рабочем переключении убрать прямой запуск mako в Hyprland и исключить
   пакетную D-Bus активацию mako на время проверки обратимым способом. Конкретный
   способ выбрать по устройству рабочей D-Bus; простого disable unit недостаточно.
   Остановить mako, запустить обновлённый лаунчер и проверить владельца имени.
6. Проверить новую сессию, восстановление после сбоя и реальные приложения.
   После успешной приёмки удалить пакет mako и повторно проверить запуск.
7. Откат: остановить нового владельца, при необходимости восстановить пакет mako,
   прежнюю активацию и конфигурацию запуска, запустить mako и проверить владельца.
   Не запускать одновременно два претендующих сервера. Живые действия и сообщения
   из mako не обещать перенести: миграция его частной истории не входит в объём.

## Критерии приёмки

| Сценарий | Ожидаемый результат |
| --- | --- |
| Лаунчер скрыт | Приём и popup продолжаются; открытие Alt+3 показывает историю |
| Перезапуск процесса | История, картинки и DND восстановлены; старых действий и черновиков нет |
| Четыре обычных сообщения | До трёх видны; у четвёртого полный срок после выхода из очереди |
| Hover / ответ / Critical / timeout=0 | Пауза либо отсутствие автоистечения по соответствующему правилу |
| Ручное закрытие / истечение | Запись прочитана, остаётся в истории, живые действия закрыты |
| Просмотр / DND / lock / unknown | Непрочитанные не становятся прочитанными из-за показа или скрытия |
| DND или lock во время показа | Карточки и очередь скрыты сразу; после снятия не воспроизводятся |
| Replacement | Одна запись, обновлённое содержимое; показанный таймер сброшен, скрытый popup не воскресает |
| Transient | Нет записи и файла в архиве; при подавлении нет popup |
| Actions и reply | Доставляются живому приложению; закрытые и восстановленные записи не имеют рабочих кнопок |
| Черновик и Esc | Текст остаётся в памяти; таймер не идёт во время ввода; после рестарта черновика нет |
| Backspace на карточке / стопке | Удалена карточка / вся стопка, включая popup и очередь; в поле удаляется только текст |
| Поиск / фильтр / навигация | Только подходящие записи, группировка сохранена, фокус и выбор не указывают на удалённую запись |
| 7 дней / 500 записей / очистка | Архив ограничен, связанные картинки удалены, живые связи удалённых записей завершены |
| Ошибка изображения / повреждённый архив | Приём продолжает работать; текст без изображения остаётся доступен при ошибке копирования |
| Смена монитора / отключение | Показанные карточки не прыгают вслед за фокусом; отключённый монитор не теряет карточки |
| Lock при старте / reconnect | До достоверного unlock нет всплывающего текста; старые сообщения затем не всплывают |
| Новая сессия / сбой / D-Bus активация | Единственный владелец org.freedesktop.Notifications — процесс лаунчера; mako не возвращается |

Итоговая приёмка требует протокольных проверок, визуальной проверки Quickshell
и проверки рабочей сессии. Успешный HTML-прототип или active у systemd unit
сами по себе не доказывают готовность замены.
