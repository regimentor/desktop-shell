# Как общая строка приложения отражает разные состояния потоков

## Question

Какое значение показывает общий ползунок приложения, если его потоки имеют разные громкости, и как он меняет их пропорционально в пределах диапазона?

Согласовано сохранение соотношения потоков и штатное чтение состояния. Требуется определить агрегат: например, максимум уровней вместо среднего; правила выхода из нуля без собственного долговременного хранения; границы при уровне потока выше диапазона ползунка; шаг и диапазон контролов приложения/потоков. Проверить на числовых примерах, включая внешнее изменение одного потока и появление нового.

Также определить отображение смешанного mute и разных фактических выходов потоков: общий toggle уже согласован, а отдельного выбора выхода потока в UI нет. Использовать штатное состояние как источник истины и не заменять его фиктивным единым значением. Решение завершает уточнение общих контролов перед составлением спецификации и её проверочных сценариев.

## Comments

Вопрос стал конкретным после выбора штатного восстановления и штатной реакции на потерю выхода: лаунчер должен уметь отображать реально разные состояния потоков, не нормализуя их при открытии.

Пользователь выбрал агрегат: «самый громкий». Общий уровень приложения — максимум настроенных громкостей его потоков (не измеренная громкость аудиосигнала). Изменение максимума должно сохранять согласованные соотношения: например, 80%/40% → 60%/30% при установке общего уровня 60%.

Предложения для завершения решения: нулевые пропорции помнить только в памяти текущей группы потоков, если они известны до обнуления; иначе при подъёме из общего нуля задавать одинаковый уровень. Диапазон 0–100% и шаг 5 процентных пунктов применять также к приложениям/потокам, значения выше 100%, пришедшие извне, показывать честно числом. При смешанном mute показывать частичное состояние, при разных выходах — «Разные выходы». Эти детали пока не согласованы.

Пользователь подтвердил предложенные правила выхода из нуля, диапазона/шага и обозначения смешанных состояний.

## Answer

- Общая громкость приложения — максимум настроенных громкостей его существующих потоков, включая muted-потоки. Mute не обнуляет сохранённое значение громкости; это не измеритель текущего аудиосигнала.
- При установке общего уровня N и прежнем максимуме M > 0 каждый уровень V становится V × N / M. Например, 80/40 → 60/30 при N=60. Отдельный ползунок меняет только свой поток, после чего максимум пересчитывается. Внешние изменения и новые потоки также пересчитывают отображаемый максимум без записи остальным.
- При обнулении известные пропорции сохраняются только в памяти для текущей группы потоков. При подъёме из нуля они используются, если известны для всего текущего состава. Если нет — все потоки получают одинаковый выбранный уровень. После изменения состава или перезапуска недостающие пропорции не угадываются и с диска не восстанавливаются.
- Ползунки приложения и потоков задают 0–100%; стрелки меняют на 5 процентных пунктов. Пропорциональные значения не округляются принудительно к шагу стрелок. Внешние уровни выше диапазона не исправляются при чтении: фактическое число отображается, ползунок ограничен своей шкалой; пользовательская установка действует в диапазоне 0–100%.
- Смешанный mute показывается как «Частично заглушено», действие общего toggle остаётся ранее согласованным. При разных фактических выходах показывается «Разные выходы»; выбор конкретного выхода запрашивает перенос всех текущих потоков приложения.

Прототип обновлён: общая громкость вычисляется из потоков, индивидуальные изменения пересчитывают максимум, подъём из нуля работает по этим правилам; частичный mute отображается текстом. Это модель интерфейса, не проверка преобразования шкалы реального PipeWire API.
