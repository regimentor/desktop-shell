# Управление звуком в лаунчере

Status: resolved
Labels: wayfinder:map

## Destination

Согласованная спецификация управления звуком в лаунчере: поведение интерфейса, модель звукового приложения и технический путь интеграции без открытых решений, мешающих реализации. Реализация — отдельный этап.

Результат: [спецификация для реализации](spec.md).

## Notes

- Использовать wayfinder; для обсуждения решений — grilling и domain-modeling, для исследования — research, для макета — prototype.
- Пользователь подтвердил PipeWire; выбор конкретного интерфейса зафиксирован в решении о механизме переключения выхода ниже.
- Над основным блоком лаунчера расположены две отделённые иконки-«облачка»: Apps и «Звук». Под ними подписи Alt+1 и Alt+2; сочетания переключают режимы.
- При переходе в «Звук» по умолчанию доступно управление общей громкостью. Поиск фильтрует звуковые приложения.
- Пользователь подтвердил: показывать существующие аудиопотоки, включая паузу и mute. Управление приложением и потоками определено в соответствующем решении ниже.
- Для приложения нужны громкость, выбор устройства вывода и mute всех его потоков; цель системных контролов уточнена решением о модели PipeWire ниже. Громкость управляется стрелками влево/вправо и перетаскиванием ползунка мышью.
- Подтверждения выше — исходные требования, а не решения закрытых дочерних билетов.
- Трекер: локальные Markdown-файлы; зависимости — Blocked by, завершение — Status: resolved и раздел Answer. Следующий билет — первый open без незавершённых зависимостей.
- На момент создания карты рабочий каталог не является Git-репозиторием (`git status` сообщает not a git repository). Исследование сохраняется локально со ссылкой из билета; ветку research/ создать здесь нельзя.

## Decisions so far

<!-- Только краткие ссылки на разрешённые дочерние билеты. -->

- [Возможности интеграции PipeWire с Quickshell](issues/01-pipewire-integration.md): громкость и mute доступны; перенос потока требует дополнительного интерфейса и проверки runtime-предпосылок.
- [Что означают общая громкость и полный mute системы](issues/02-system-controls.md): согласованы диапазон и шаг, сохранение уровней при mute и доступность ползунка при поиске; охват пересмотрен решением о модели PipeWire.
- [Как управлять несколькими потоками одного приложения](issues/03-app-controls.md): согласованы общий и отдельный уровни управления и toggle mute всех потоков; восстановление уточнено отдельным решением.
- [Какой механизм переключения выхода поддерживает лаунчер](issues/05-routing-contract.md): выбран WirePlumber через pw-metadata и подтверждение фактического результата; потеря выхода уточнена отдельным решением.
- [Как выглядят режимы и работает управление с клавиатуры и мыши](issues/04-launcher-interaction.md): выбран вариант A с ползунком в строке приложения; согласованы навигация, переключение режимов, очистка поиска и Esc.
- [Как системная громкость следует модели PipeWire](issues/06-global-volume-model.md): системные контролы следуют устройству по умолчанию и его фактическому состоянию; отдельный регулятор всех выходов исключён.
- [Как узнавать приложение и восстанавливать его настройки](issues/07-app-identity.md): восстановление принадлежит WirePlumber, лаунчер читает живое состояние; собственное хранение и сброс mute после закрытия исключены.
- [Как лаунчер реагирует на потерю выхода](issues/08-disconnected-output.md): принята штатная политика WirePlumber, включая возможный автоматический переход; собственное удержание без звука исключено.
- [Как общая строка приложения отражает разные состояния потоков](issues/09-app-row-state.md): выбран максимум громкостей; согласованы пропорции, выход из нуля, диапазон/шаг и смешанные состояния.
