# Управление звуком в лаунчере

Status: ready-for-agent
Implementation: complete

## Назначение

Добавить в существующий QML-лаунчер режим «Звук»: управление выходом по умолчанию, приложениями и их отдельными аудиопотоками. Планирование и реализация завершены. Triage-статус отражает готовность спецификации; результат реализации указан отдельно и описан ниже.

Каноническая история — [карта решений](map.md). Детальные правила хранятся в разрешённых билетах по ссылкам ниже; их Answer имеет приоритет над историческими Comments и демонстрационным кодом. Прежние предложения глобального управления всеми выходами, собственного хранения настроек, сброса mute после закрытия и удержания приложения без звука при потере выхода отменены позднейшими решениями.

## Согласованный интерфейс

Использовать обновлённый вариант A из [прототипа](../../launcher/audio-prototype.html?variant=A): дерево приложений и раскрываемых потоков в цветах текущего лаунчера. Ползунок и mute приложения находятся в строке его названия; ниже расположен выбор выхода. Системные контролы остаются над результатами поиска.

Над основным блоком — две отдельные иконки-«облачка», Apps и «Звук», с подписями Alt+1 / Alt+2. Открытие начинает с Apps и пустого запроса; переход в звук выбирает системную громкость. Поиск звуковых приложений учитывает существующие потоки, включая mute/паузу. Браузерная вкладка доступна отдельно только если представлена отдельным потоком.

Полный контракт клавиатуры, очистки поиска и фокуса: [Макет и управление](issues/04-launcher-interaction.md). Системный диапазон и шаг: [Системные контролы](issues/02-system-controls.md).

## Модель и технический путь

| Область | Принятое направление | Детальное решение |
| --- | --- | --- |
| Системная громкость | Текущий выход по умолчанию, его фактические громкость и mute | [Модель PipeWire](issues/06-global-volume-model.md) |
| Приложение и потоки | Общие действия приложения плюс отдельные громкость/mute потоков | [Два уровня управления](issues/03-app-controls.md) |
| Общий ползунок | Максимум потоков; пропорциональное изменение; явно смешанные состояния | [Общая строка приложения](issues/09-app-row-state.md) |
| Наблюдение | Quickshell.Services.Pipewire, привязанные и готовые узлы, события изменений | [Исследование API](issues/01-pipewire-integration.md) |
| Переключение выхода | WirePlumber через pw-metadata, подтверждение фактических связей | [Механизм переноса](issues/05-routing-contract.md) |
| Восстановление | Штатная политика WirePlumber, без отдельного хранилища лаунчера | [Идентичность и состояние](issues/07-app-identity.md) |
| Потеря устройства | Текущая политика WirePlumber, без собственной блокировки и automute | [Потеря выхода](issues/08-disconnected-output.md) |

Группировка и временная память пропорций не являются отдельным источником фактической громкости. Открытие лаунчера не нормализует уровни, не снимает mute и не переносит потоки. Произвольное совпадение отображаемого имени не доказывает принадлежность одному приложению.

Точки интеграции: существующие `launcher/Launcher.qml`, `launcher/AppModel.qml`, `launcher/Theme.qml`. Не переносить демонстрационный HTML в производство: он служит первичным материалом по компоновке. В QML потребуется включить облачки в геометрию окна и входную маску, а горячие клавиши обрабатывать при фокусе в любом контроле.

## Проверочные сценарии реализации

1. Повторный вызов, Alt+1/2, ввод/очистка поиска и Esc выполняют контракт. Облачки кликабельны; мышь и клавиатура работают с ползунками. Раскрытие потоков не конфликтует с ←/→. Список устройств получает собственную навигацию и закрывается без случайного изменения громкости.
2. Смена выхода по умолчанию переключает системные контролы на его реальные значения. Другой выход не меняется. Если выхода нет или узел не готов, нет исключения и активной записи в несуществующий узел.
3. Потоки 80/40 дают общий 80; установка 60 даёт 60/30. Изменение одного потока пересчитывает максимум, не меняя второй. Mute потока не убирает его из списка и не обнуляет его числовую громкость.
4. Переход 80/40 → 0/0 → 60/30 сохраняет известные пропорции текущей группы. Начальное 0/0 без известной истории при установке 30 даёт 30/30. Внешнее значение за пределами шкалы не нормализуется при чтении.
5. При частичном mute общий toggle глушит все; следующий включает все. Системный mute действует на выход и не переписывает mute потоков. Изменение ползунка при mute само звук не включает.
6. Новый или исчезнувший поток обновляет список и общий максимум. Исчезновение последнего потока не трактуется как команда сбросить mute. После перезапуска оболочки отображается состояние, восстановленное WirePlumber.
7. Выход приложения меняется для всех текущих потоков; до подтверждения виден процесс переключения. Отказ одного потока, исчезновение цели и разные фактические выходы не отображаются как полный успех.
8. Отключение и возвращение устройства следуют политике WirePlumber. Интерфейс показывает новый фактический выход либо отсутствие связи, без собственного удержания звука и изменения настроек автомьюта.
9. Отсутствие метаданных, несколько процессов, одинаковые названия разных приложений и потоки браузера не вызывают необоснованного объединения. Эвристика иконки не становится ключом состояния.

Эти сценарии — требования к проверке будущей реализации, не отчёт о пройденных тестах. Проверить преобразование шкалы Quickshell/PipeWire по реальному API; не добавлять кубическое преобразование на основании предположения. Проверить сохранение баланса каналов и обратную связь внешних изменений без циклической перезаписи.

## Состояние проверки и границы

### Реализация 2026-09-05

Добавлены `AudioModel.qml`, `AudioMath.js`, `AudioRouter.qml`, `AudioControls.qml` и `AudioPane.qml`; режимы интегрированы в `Launcher.qml`. Установщик включает новые файлы. Инструкции и полный снимок кода обновлены в [документации](../../docs/launcher.md).

Пройдены [математические проверки](../../tests/audio/math.test.cjs), [интеграционный тест](../../tests/audio/shell.qml) с отдельной PipeWire/WirePlumber-сессией и [Wayland UI-тест](../../tests/audio/ui.qml). Виртуальные выходы проверяют реальные операции громкости, mute, смены default и metadata-переноса, пропорции и баланс через ноль, новый состав группы, частичный отказ, отключение цели, запрет переноса и отсутствие устройств. UI-тест проверяет поиск, режимы, Esc, клавиатурную навигацию, дерево, picker, Tab и мышиное перетаскивание. Итоговый PNG панели просмотрен. QML lint и bash syntax проходят с известными предупреждениями метаданных Quickshell о PanelWindow и QProcess::ExitStatus.

Исходник Quickshell 0.3.1 подтверждает готовую визуальную шкалу: дополнительное кубическое преобразование не добавлено. Для состояния связей привязаны сами PwLinkGroup; привязки только отдельных PwLink недостаточно. Баланс каналов через ноль сохраняется в памяти, поскольку штатный setter сохраняет пропорции лишь при ненулевом среднем.

Пользовательская аудиосессия проверялась read-only. Установленная копия в `~/.config/quickshell/daevox-launcher` не обновлялась; обновление выполняет `./install-launcher.sh`. Физические отключения Bluetooth/HDMI, физическая клавиатура EN/RU и compositor hit-testing при клике снаружи остаются ручной приёмкой.

### Состояние на момент планирования

Подтверждены документацией возможности API и read-only предпосылки окружения: Quickshell 0.3.1 по документации проекта; работающие PipeWire 1.6.8 и WirePlumber 0.5.17, наличие pw-metadata и разрешённый перенос. Реальные операции со звуком не выполнялись. JavaScript прототипа проходит проверку синтаксиса; подключённого браузера для автоматизированной визуальной проверки нет. Выбор макета подтверждён пользователем.

Микрофоны, запись, эквалайзер, эффекты и изменение общей конфигурации аудиосистемы не входят в реализацию этой спецификации. Существующая функциональность запуска Apps должна сохраниться. Проверить штатные проверки проекта и сценарии выше в целевой сессии при реализации.
