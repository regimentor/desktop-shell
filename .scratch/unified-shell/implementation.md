# Реализация единой оболочки

Реализован единый production `shell.qml` с `DesktopState`, `BarRuntime`,
`Launcher` и условным `NotificationRuntime`. Старые production roots удалены;
шаблоны старых сервисов сохранены только в fixtures. Незакоммиченные изменения
уведомлений, существовавшие до этой задачи, перенесены вместе с модулями.

Рабочий код соответствует целевому дереву. Общий DesktopState сохраняет
транспорт, переподключение и защиту от устаревших ответов. Панель получает
раскладку, состояние окон и координаты через его интерфейс. Лаунчер и popups
используют общий выбор экрана, захват фокуса остаётся у лаунчера. Аудиомодели
остаются внутри лаунчера. Уведомления работают при закрытом окне и отключаются
без загрузки нативного endpoint. IPC target, команды и формат status сохранены.

`install-shell.sh` собирает нативный модуль и проверяет QML до остановки
сервисов. При успешной активации через IPC очищает legacy по явным manifests.
Параметры окружения, внешние EnvironmentFile и существующая D-Bus-активация
переносятся; включение уведомлений сохраняется, в том числе из user manager.
При ошибках восстановления прежние файлы и настройки остаются в отдельной
резервной копии. Новая установка требует активную графическую сессию для
проверки готовности перед очисткой старых файлов.

`uninstall-legacy.sh` использует общую библиотеку установки. Поддерживает bar,
launcher, all, справку и dry-run, обнаруживает ручные процессы, не следует
ссылкам, сохраняет неизвестные файлы и каталоги, drop-in, историю и старый shared.
Старые установщики служат обёртками единого CLI.

## Проверки после реального перехода

Установка в пользовательскую сессию не выполнялась: задача разрешала разработку
и проверки перехода, но не само развёртывание. Поэтому отдельно остаются:

- настоящий переход двух user units на один и повторный вход в UWSM-сессию;
- физическое подключение/отключение мониторов во время работы оболочки;
- меню реальных tray-приложений под общей Adwaita и уведомления реальных приложений;
- блокировка настоящей пользовательской сессии и поведение после её разблокировки.

Автоматизированные проверки покрывают правила hotplug и блокировки, фокус UI,
два доступных монитора, установку/откат через подставной systemctl и настоящий
единый runtime. Они не заменяют перечисленную проверку пользовательской сессии.

## Исправление зависания установки

После удаления legacy units пользователь запустил установщик при оставшейся
D-Bus-активации старого лаунчера. Установщик выбирал Type=dbus, хотя флаг
уведомлений уже отсутствовал; systemd ждал org.freedesktop.Notifications 90 секунд.
Регрессионный тест воспроизвёл этот сценарий до исправления.

Сервис теперь всегда явно использует Type=exec: необязательный endpoint не
определяет готовность всей оболочки. BusName для существующей активации
сохраняется. Добавлены ограничение ожидания systemctl, таймауты unit и вывод
каждого этапа изменения сервисов. 20 тестов установки прошли.

После исправления установка в пользовательскую сессию выполнена в рамках
устранения зависания. daevox-shell.service подтвердил active/running,
launcher status вернул корректный ответ, аудио готово. Уведомления отключены;
прежний drop-in notifications.conf сохранён в daevox-launcher.service.d.
Указанная выше оговорка о невыполненной реальной установке относится к первому
проходу реализации; проверки физического hotplug и нового входа остаются ручными.

## Восстановление уведомлений после удаления legacy unit

2026-09-08: Найден сохранённый старый drop-in с DAEVOX_NOTIFICATIONS=1.
При LoadState=not-found systemd не возвращал его Environment. Установщик теперь
читает явную настройку уведомлений из оставшихся legacy drop-in; параметры
существующего единого сервиса сохраняют приоритет. Регрессионный тест сначала
падал, после исправления прошли все 21 проверки установки.

В рабочем daevox-shell.service восстановлен флаг через отдельный drop-in.
После перезапуска notifications.ready=true, D-Bus-владелец совпадает с MainPID
оболочки. История доступна (262 записи на момент проверки), центр открыт.
