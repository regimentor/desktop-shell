## Question

Входные факты: [проверка установленной модели](../research/installed-window-model.md). Встроенная модель в живой пробе недосчитывает монитор и возвращает null вместо активного окна, тогда как прямые снимки содержат данные. Выбор источника состояния должен явно учитывать это расхождение. Значение `usingLua` само по себе не подтверждает поддержку Lua-dispatch.

Какой стек и структура `bar/` обеспечивают согласованное поведение? Где проходит граница прямого Hyprland IPC и встроенных адаптеров Quickshell? Как обрабатывать начальный снимок, события, переподключение, hotplug мониторов и поиск иконок? Как запускать панель и поддерживать соответствие теме launcher? Определить обязательные проверки будущей реализации и ограничения поддержки трея.

## Comments

### Подтверждён источник состояния и команд

Пользователь: «да прямой Hyprland IPC».

Панель получает состояние Hyprland и отправляет команды напрямую через его Unix-сокеты. Встроенные модели `Quickshell.Hyprland` и процессы `hyprctl` не являются транспортом панели. Это решение относится к взаимодействию с композитором; трей и системные иконки используют свои службы.

### Подтверждение архитектуры

Пользователь подтвердил Quickshell/QML с отдельным IPC-клиентом, независимый процесс и сервис панели, автоматическое восстановление IPC. Вместо отдельных копий темы запросил выделить общую тему для launcher и панели: «1 да; 2 да; 3 выделяем; 4 да».

## Answer

### Компоненты и источники данных

- Стек — Quickshell/QML. `bar/shell.qml` создаёт одно общее состояние и панели по экранам. IPC-клиент и модель не дублируются на каждый монитор.
- `bar/HyprlandIpc.qml` отвечает за прямые Unix-сокеты через `Quickshell.Io.Socket`: `.socket.sock` для запросов/команд, `.socket2.sock` для событий. Ни встроенные модели `Quickshell.Hyprland`, ни процессы `hyprctl` не являются источником состояния панели.
- `bar/HyprlandState.qml` хранит нормализованные снимки мониторов, воркспейсов, окон, активного окна и устройств ввода. Компоненты модулей получают состояние из этой модели и вызывают её действия; не разбирают строки протокола самостоятельно.
- Окно идентифицируется IPC-адресом в рамках текущего соединения; при полном восстановлении старые ссылки сбрасываются. Для стартового снимка используется стабильный порядок, затем новые окна добавляются в порядке появления. Нельзя обещать восстановление исторического порядка запуска из снимка, который его не гарантирует.
- Заголовок монитора берётся из последнего сфокусированного существующего окна текущего воркспейса. При старте используются сведения `lastwindow` воркспейса и активного окна; история обновляется событиями фокуса. Если последнее окно закрыто, выбирается последнее оставшееся из известной истории, затем окно из снимка; пустой воркспейс не имеет заголовка.
- Трей использует `Quickshell.Services.SystemTray`, меню — API меню Quickshell. `onlyMenu` открывает меню и по левому клику. Иконки трея, включая passive-элементы, не прячутся за стрелку; отсутствие меню или неподдерживаемого действия не вызывает ошибку интерфейса.
- `bar/AppIconResolver.qml` сопоставляет IPC `class/initialClass` с `DesktopEntries`: точный id, затем эвристический поиск, затем стандартная иконка приложения. Результаты кэшируются; отсутствие совпадения не скрывает окно. Реальная тема иконок системная, PNG из прототипа не поставляются как набор иконок панели.
- Раскладка читается из снимка `devices`; выбирается клавиатура с признаком main, при отсутствии — первая доступная. Изменения раскладки и конфигурации инициируют обновление. EN/RU — примеры меток, цикл включает все настроенные раскладки. При отсутствии клавиатуры отображается `—`, действие отключено.

### Начальная загрузка, события и восстановление

- При запуске сначала подключить поток событий, затем прочитать `version`, `monitors`, `workspaces`, `clients`, `activewindow`, `devices`. События, пришедшие во время снимка, помечают соответствующие данные устаревшими и вызывают повторное чтение; старые ответы из предыдущего соединения отбрасываются.
- Очередь сериализует запросы через один логический request-канал. На каждый запрос открывается соединение, ответ собирается целиком до закрытия сервером. Частичный read не считается полным JSON. Команду не отправлять, пока предыдущая не завершена.
- События разбираются построчно с сохранением неполного хвоста между чтениями. Неизвестное событие не обрывает соединение; обновления связанных снимков объединяются короткой задержкой. Данные не перечитываются непрерывным циклом таймера при здоровом соединении.
- Переключение воркспейса, фокус окна, special и раскладки идут прямыми командами IPC. После подтверждённого действия перечитывается затронутое состояние. Не выбирать синтаксис по ненадёжному `Quickshell.Hyprland.usingLua`: целевая версия определяется прямым `version`, команды проверяются на Hyprland 0.56.2 при реализации.
- На timeout, обрыв или некорректный ответ текущая загрузка считается неготовой; данные Hyprland не выдаются за актуальные. Workspaces и заголовок очищаются, lang показывает `—`, соответствующие действия отключены. Часы и трей продолжают работать, если сама Wayland-сессия доступна.
- Повторное подключение — с увеличением задержки до ограниченного максимума; после него полный снимок и новая готовность. Не переигрывать автоматически команду, чей результат после обрыва неизвестен.
- `Quickshell.screens` управляет жизнью окон панели; IPC-мониторы сопоставляются по имени выхода. При hotplug обновляются модели и набор панелей, без смешивания воркспейсов разных мониторов. При отсутствии сопоставления Hyprland-модули этого экрана недоступны до нового снимка.
- Изменение instance при полном перезапуске compositor обслуживается перезапуском процесса в новой графической сессии с новым окружением; нельзя обещать сохранение старого Wayland-соединения при завершении compositor.

### Общая тема

- Выделить общий источник `shared/DaevoxTheme.qml`: палитра, семейство Monoid и общие семантические цвета. Launcher и панель импортируют один компонент через локальные `Theme.qml`.
- `launcher/Theme.qml` сохраняет геометрию launcher, `bar/Theme.qml` — утверждённую геометрию компактного A. Радиусы и размеры панели не заменяют размеры launcher.
- Общие значения переносятся из текущего launcher без визуальных изменений launcher. Его адаптация к общей теме и обновление установщика входят в будущую реализацию по явному запросу пользователя; остальные изменения launcher вне области работы.
- В исходниках оба адаптера используют `../shared`. При установке сохранить ту же относительную структуру: `~/.config/quickshell/daevox-launcher/`, `~/.config/quickshell/daevox-bar/` и `~/.config/quickshell/shared/DaevoxTheme.qml`. Не удалять чужие файлы из shared.
- Оба установщика доставляют общую зависимость из одного источника и проверяют её наличие. Замена общего файла атомарная; интерфейс общих токенов сохраняется совместимым с обоими адаптерами. Существующий путь launcher и команда его открытия сохраняются.

### Запуск и поддержка

- Панель запускается отдельно: `qs --no-duplicate --path bar/shell.qml` из исходников; установленная — пользовательским `daevox-bar.service`, привязанным к графической сессии по образцу launcher.
- Будущий `install-bar.sh` устанавливает runtime панели, общую тему и unit; содержимое `bar/prototype/` не входит в runtime. Запуск/остановка launcher и панели независимы.
- Первая целевая связка: установленный Quickshell 0.3.1 и Hyprland 0.56.2. Поддержка других версий не предполагается без проверки. Несовместимый ответ не маскируется как корректная пустая модель.
- Верхние PanelWindow резервируют место под панель и верхний отступ. Установленная геометрия должна включать всю видимую высоту и не перекрывать обычные окна; отсутствие дополнительного нижнего зазора соответствует выбранному прототипу.

### Критерии готовности будущей реализации

1. На обоих мониторах панель соответствует компактному A; пять модулей расположены как согласовано. После выделения общей темы launcher выглядит и работает как раньше.
2. Открытие/закрытие/перенос окон, смена заголовка и фокуса, пустой workspace и special обновляются без дубликатов и потерянных иконок. Несколько окон одного приложения видны отдельно. Проверяется и старт при уже открытых окнах.
3. Клики выполняют нужное переключение/фокус; колесо над workspaces ничего не переключает. Проверяется прямой IPC без запуска hyprctl или отдельного процесса на событие.
4. Модель совпадает с прямыми снимками обоих мониторов. Переподключение и hotplug не оставляют старое состояние. При обрыве недоступные действия выключены, часы/трей продолжают работать в живой Wayland-сессии.
5. Проверяются частичные ответы и события, несколько событий в одном read, события во время снимка, timeout, некорректный JSON и поздний ответ старого соединения. Для этих случаев нужны воспроизводимые проверки транспорта/модели, а не только визуальный запуск.
6. Раскладка переключается по клику и обновляется при внешнем переключении. Часы корректны при смене минуты/даты. Трей проверяется на реальных приложениях: иконки, подсказки, меню, левый/правый/средний клик и колесо там, где они поддержаны.
7. 30 окон на ширине 1024 px остаются в одной строке, правая часть не перекрывается, заголовок уступает место. Проверяются длинный заголовок, отсутствие иконки, пустой workspace и выбранные размеры на реальном масштабе монитора.
8. Установка из произвольного рабочего каталога, повторная установка, независимые запуск/остановка сервисов и загрузка общего компонента работают. В runtime нет демонстрационных данных или переключателя вариантов прототипа.

Критерии здесь задают проверку реализации; их прохождение пока не заявляется. Все архитектурные решения для начала реализации определены, работа этой карты остаётся планированием.
