# Проверка установленной модели окон

Проверено в живой сессии пользователя 2026-09-06. Локальные версии: Quickshell 0.3.1 (Arch Linux), Hyprland 0.56.2, commit `efb50993780079460b0cbed1363e2166a2de1d9f`.

## Воспроизведение

- [QML-проба](../probes/window-model.qml): `qs --no-color --path .scratch/bar/probes/window-model.qml` из корня проекта. Не создаёт окон, не посылает dispatch, не меняет фокус. Явно запрашивает снимки при загрузке, повторяет чтение через 1,5 секунды, печатает сводку через 4 секунды и завершается.
- [Прямая IPC-проба](../probes/ipc-snapshot.py): `python3 .scratch/bar/probes/ipc-snapshot.py`. Последовательно читает JSON-ответы version, monitors, monitors all, activewindow, clients, workspaces из `.socket.sock`. Печатает только выбранные поля, не полные заголовки или адреса окон.
- Нужен доступ к сокетам текущей Wayland/Hyprland-сессии. В песочнице соединение заблокировано; проверки выполнены с одобренным доступом к сессии.

## Подтверждённый контракт

Для всех 9 окон QML-проба установила:

| Проверка | Результат |
| --- | --- |
| Тип элемента `Hyprland.toplevels.values` | `qs::hyprland::ipc::HyprlandToplevel` |
| `window instanceof HyprlandToplevel` | `true` |
| `window.address` | Непустая строка |
| `window.title` | Строка |
| `window.workspace` | `HyprlandWorkspace`; окно присутствует в `workspace.toplevels.values` |
| `window.appId` | `undefined` |
| `window.lastIpcObject.class`, `initialClass` | Доступны |
| `window.wayland` | `qs::wayland::toplevel::Toplevel` |
| `window.wayland.appId` | Доступен у всех наблюдавшихся окон |
| `window.wayland.HyprlandToplevel.handle === window` | `true` |
| `window.monitor` после повторного снимка | `HyprlandMonitor` у всех наблюдавшихся окон |

Установленный файл `/usr/lib/qt6/qml/Quickshell/Hyprland/_Ipc/quickshell-hyprland-ipc.qmltypes` также объявляет `activeToplevel` как указатель на `HyprlandToplevel`. Живое ненулевое значение этой property получить в пробе не удалось: см. расхождения ниже. Нельзя трактовать документационные ссылки на Wayland Toplevel как фактический тип элементов этой установленной модели.

## Расхождения со снимком прямого IPC

| Показатель | QML, после повторного refresh и 4 секунд | Прямой IPC, соседняя проверка |
| --- | --- | --- |
| Окна | 9 | 9 |
| Мониторы | 1 | 2 (`DP-3`, `DP-2`) |
| Воркспейсы | 6 | 7 |
| Активное окно | `null` | Непустой объект с адресом |
| Связь экранов с монитором | 1 из 2 | Оба монитора есть в `monitors` |
| Active workspace у сопоставленного QML-монитора | Отсутствует | У обоих мониторов есть `activeWorkspace` |

Первый запуск без предварительной инициализации singleton прочитал пустую модель сразу после первого обращения. После явного начального refresh окна появились, но мониторов ещё не было. Повторный refresh позволил получить один монитор; второй и activeToplevel оставались недоступны. Это не доказывает точную причину: снимки не атомарны между процессами, корневая причина расхождения не установлена.

`Hyprland.usingLua` после загрузки равно `true`; версия из прямого IPC — 0.56.2. Поддержка Lua-dispatch не проверялась, команды изменения состояния не отправлялись. Нельзя выбирать синтаксис команд только на основании этого флага без проверки совместимости.

## Следствие для архитектурного решения

Доступ к типам и данным окон подтверждён; полнота встроенной модели мониторов и активного окна для этой сессии не подтверждена. Прямые read-only запросы возвращают необходимые снимки. При выборе архитектуры следует либо объяснить и устранить расхождение встроенной модели, либо опираться на прямые снимки IPC для этих данных. Это варианты, а не принятое архитектурное решение.

Не проверены dispatch, события при изменениях, reconnect, hotplug, special, поиск иконок или трей. Эти пробы не являются реализацией панели и не подтверждают её готовность.
