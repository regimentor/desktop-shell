# Прототип центра уведомлений — временный

Вопрос: как разместить группированную историю, действия и быстрый ответ
в существующем лаунчере шириной 560 px, вместе с новым третьим режимом,
и как выглядят всплывающие карточки под панелью?

Из корня репозитория:

```bash
python3 -m http.server 8767 --bind 127.0.0.1 --directory launcher
```

Открыть http://127.0.0.1:8767/notification-prototype.html?variant=A.
Самостоятельный HTML также можно открыть как локальный файл.

- A — раскрывающиеся стопки по приложениям, обновлённые по запросу пользователя.
  Последнее сообщение лежит сверху, за ним видны края остальных карточек.
  Нажатие раскрывает стопку, «Свернуть» собирает её обратно. Поиск раскрывает
  совпадения. Одиночное уведомление показывается обычной карточкой.
- B — компактный сгруппированный список слева и выбранное сообщение справа.
- C — две колонки приложений с раскрытыми группами.

Варианты переключаются нижней полосой и стрелками ←/→ вне полей ввода.
URL сохраняет выбранный вариант. Смена варианта сохраняет тестовые данные.
Макет воспроизводит окружение лаунчера и палитру общей темы; это HTML,
а не реализация Quickshell. Apps и Volume показаны как заглушки соседних режимов.

Для ссылки на раскрытый пример: `?variant=A&stack=telegram`.
Обновлённый вариант A со свёрнутыми стопками подтверждён пользователем.
Первичный образец: `prototype/launcher-notifications`, коммит `be2d9dd`.

Слева находятся только средства демонстрации: пустая история, плотная история,
архив после перезапуска, новое/временное уведомление, всплеск из пяти сообщений,
блокировка и пауза таймеров. Начальная пауза даёт сравнить макеты; кнопка запускает
пятисекундные таймеры. Важная карточка не истекает автоматически.

Работают поиск, фильтр непрочитанных, сворачивание и очистка групп, удаление,
закрытие с сохранением прочитанной записи, «Не беспокоить», очередь до трёх
карточек, быстрый ответ в центре и непосредственно во всплывающей карточке.
Все сообщения вымышленные, ответы и действия лишь меняют состояние демо.

Предложение клавиатуры: Alt+1/2/3 переключают режим, ↑/↓ из поиска выбирают
запись, Enter из поиска вызывает действие/раскрытие, Tab обходит контролы.
Esc закрывает ответ, затем очищает поиск, затем скрывает лаунчер. Del вне
поля ввода удаляет выбранную запись. ←/→ внизу служат сравнению вариантов,
а не предлагаемой клавиатуре готового продукта. Браузер может перехватить
свои сочетания клавиш — это не проверка Wayland focus или compositor shortcuts.

Реальное хранение на диске, 7 дней/500 записей, D-Bus, приём уведомлений,
системная блокировка, hotplug, изображения из приложений и перенос с mako
здесь не реализуются. Архив после рестарта и блокировка представлены сценариями.
В настоящем приложении они требуют отдельных проверок по спецификации.

JavaScript прошёл node --check, все три варианта отрисованы в отдельном
headless Chromium и просмотрены. Интерактивный CUA-браузер недоступен;
живое взаимодействие этим инструментом не проверялось.
